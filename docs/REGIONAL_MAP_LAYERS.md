## Runtime layers

`data/regionalMaps.js` defines the active region artwork without changing the gameplay graph in `data/illustratedWorldMap.js`. `ui/RegionalMapRenderer.js` creates six independent world-space containers. All containers inherit the map camera's pan and zoom; the full-screen UI camera remains separate.

| Layer | Depth | Purpose |
| --- | --- | --- |
| terrain | 0 | Current complete Pineshire illustration; eventually approved base terrain |
| routes | 10 | Future transparent painted roads and paths, aligned with traced routes |
| landmarks | 30 | Future independent buildings and destination artwork |
| environment | 80 | Existing localized ambience; future image and sprite effects |
| foreground | 120 | Transparent near scenery, below location labels and the chosen character |
| overlays | 140 | Noninteractive artwork overlays; gameplay markers remain at their existing depths |

The existing labels, location hit targets and party remain in the current scene. Labels use depths 160 and above, the party uses 500, and landmark touch targets use 900. Fixed UI overlays use depths 999 and above. Decorative layers must not own touch targets, unlocks or travel state. Future scenery remains below characters to preserve their visibility.

Each image record supplies `id`, texture `key`, `x`, `y`, and optionally `frame`, `width`, `height`, `alpha`, `originX`, `originY` and `animation`. Coordinates are logical image pixels. The default origin is the upper-left corner; a cropped asset must supply its original image-space offset. Records draw in array order within their layer. The existing texture key `world-pineshire-final` still uses `assets/world-map/illustrated-regions-v1/01-pineshire-reach-v4.png`, sized to 3840 by 2160 logical pixels.

Optional region `assets` entries use `{ type, key, url, data, config }`. The loader accepts images, atlases (`data` is the atlas JSON URL or object) and spritesheets (`config` supplies frame dimensions). Use Vite-resolved local asset URLs. Already loaded textures are reused. An animated record provides `animation: { type: 'frames', frames, frameRate, repeat, loop, startFrame }`, with explicit atlas frame names or spritesheet frame numbers. Frames normally use the record's texture key; individual `{ key, frame }` records also support separately loaded image sequences. Defaults are 20 FPS and infinite repetition; `loop: false` overrides repetition. Animation keys include region and artwork IDs. Set `frame` to the intended static frame for reduced-motion users. Optional `scale` multiplies the authored display dimensions.

Animated records are culled against the map camera in world space, with conservative margins for their size and drift. Invisible sprites become inactive, skipping Phaser animation updates; visible sprites resume their local playback. Scene pause/sleep stops playback and movement. Shutdown removes the renderer listener and destroys containers and effects. Reduced-motion users see the static frame. No global timers, particles, shaders or new libraries are required.

For independently painted wisps, `animation: { type: 'drift', loop: true }` can accompany `motion: { duration, driftX, driftY, scaleTo, phase, fade }`. Duration uses milliseconds, drift uses logical map pixels, phase is a fraction of the loop, and fade uses a smooth zero-opacity transition at both ends. This moves real artwork rather than generating smoke shapes. Each effect has its own visible elapsed time. Approved records belong in their named `layers` array; `pendingArtwork` is a non-rendered art handoff, not an automatically enabled effect list.

Unrelated procedural ambience is retained inside the environment container. Pineshire's `legacyAmbience` options disable geometric smoke and portal strokes and exclude the three quarry flames now represented by sprites. The painted village plumes and painted portal remain static until clean replacement art exists. Future rivers, waterfalls, smoke, foliage and portals should use small localized sprites or cropped images with shared atlases. Replace each corresponding existing ambience entry when installing its approved sprite, avoiding duplicate effects. Keep frame counts and transparent margins modest and avoid full-region animated sheets. Do not bake UI or party characters into artwork.

## Pineshire environmental proof of concept

This is a partial artwork integration, not three finished animated landmarks. The unchanged base is still `01-pineshire-reach-v4.png`. It is a flattened 1672 by 941 illustration, displayed in the existing 3840 by 2160 logical map space. The package manifest refers to an earlier source image, but no usable transparent chimney, flame, portal-interior or stone-frame layers were found in the active asset package. Existing smoke-bomb and teleport combat sheets and the Murmuring Abyss battlefield portal have a pixel-art style and framing unsuitable for this illustrated map.

The `position` helper converts these native image coordinates to logical map pixels independently of destination coordinates. Quarry flame feet use origin 0.5, 0.96 with opacity 0.88. The shared transparent runtime sheet is `assets/world-map/pineshire-environment/quarry-flame.png`: 512 by 512 pixels, four columns/four rows, 128 by 128 cells, approximately 223 KiB compressed and 1 MiB uncompressed RGBA. Three sprites reuse it with different initial phases. It is original generated painterly artwork, reduced for runtime packing, with no third-party artwork or external runtime dependency. The original painted light and flame pixels are preserved underneath; review in motion must confirm that the overlay footprint covers the painted flame cleanly at every frame. Additional surface-light flicker has not been implemented without a suitable spill mask.

A smoke-sheet candidate was created but is not loaded or shipped. A generated village clean-plate candidate was rejected because it changed chimney/roof details. Both remain in ignored `output/art-candidates/pineshire-environment/` for local review. Keeping them disabled prevents duplicate static and moving smoke and avoids substituting newly painted village geometry. No independent portal artwork has been installed, and no generic rotating circle is presented as a completed portal.

Subsequent requested alpha inspection found a genuine transparent background in the 512 by 512 flame sheet (160,498 fully transparent pixels), but also 17,650 nonzero-alpha pixels with saturated red color (R > 220, G < 30, B < 30). None of those red pixels have alpha above 220. These partially transparent red fringe/island pixels are baked into the sprite asset, so the flame proof of concept still needs a corrected export or re-authored loop before visual approval. The original map was not edited. This inspection does not constitute approval of flame edge quality or a fix to the sheet.

## Geography authority and continuity

No approved seamless master geography reference was found in the active map data or illustrated-region package. The package manifest explicitly describes later-region anchors as proposals. It contains a Highmere Crags illustration and proposed locations, but these are not a validated shared atlas. Runtime exports currently describe Pineshire only. This pass adds no Highmere runtime graph or invented geographic connections. The existing exit position, prerequisite and Highmere destination description remain authoritative for the outgoing sign.

`atlasPlacement` is deliberately null. Before adding another playable region, approve a master geography reference containing:

- A shared coordinate origin, units, north direction, terrain scale and regional image-to-world transforms.
- Region coverage polygons, boundary overlaps, matching edge crops, and surveyed connection anchors on both sides.
- Continuous road centerlines, widths and elevations; river centerlines, flow direction, watershed and bridge crossings; mountain ridges and terrain landmarks across boundaries.
- Existing runtime IDs and progression requirements for the destination and source ends of each connection. Later-region manifest proposals must be reconciled explicitly against approved source data.
- A shared perspective, lighting direction, time of day, palette, landmark scale and painterly style reference. Preserve detailed close-up geography while moving toward Town Hub's brighter finish.

Do not infer global positions from the manifest's region order or Pineshire's `column: 0`, and do not change traced Pineshire coordinates to make separately painted maps meet. Adopt a common atlas only after geography is reviewed; image-local coordinates can remain stable through explicit transforms.
